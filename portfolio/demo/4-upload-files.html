Claim declaration with file uploadDéclaration de sinistre avec dépôt de fichiers

The customer reports a claim and attaches photos or a claim form straight from their phone or computer. Each file is stored securely against the claim, and its type decides which AI analysis runs next.

Le client déclare un sinistre et joint photos ou formulaire depuis son téléphone ou son ordinateur. Chaque fichier est stocké de façon sécurisée avec le sinistre, et son type décide de l'analyse IA qui suit.

Build planPlan de réalisationPower PagesSharePointDataversePower Automate

Design choice: where files liveChoix d'architecture : où vivent les fichiers

Files go in a SharePoint document library, one folder per claim, through Power Pages document management. Their metadata stays in Dataverse. SharePoint storage is much cheaper than Dataverse storage, a lesson from my €70k storage optimisation, and advisors can open the files directly.

Les fichiers vont dans une bibliothèque SharePoint, un dossier par sinistre, via la gestion documentaire Power Pages. Leurs métadonnées restent dans Dataverse. Le stockage SharePoint coûte beaucoup moins cher que celui de Dataverse, une leçon de mon optimisation de stockage à 70 k€, et les conseillers ouvrent les fichiers directement.

RulesRègles

  • Accepted types: JPG, PNG and PDF only
  • Size limit per file, and several files allowed
  • Customers see files on their own claims only
  • Files are deleted on schedule once the retention period after closure ends
  • Types acceptés : JPG, PNG et PDF uniquement
  • Taille limitée par fichier, plusieurs fichiers possibles
  • Le client ne voit que les fichiers de ses propres sinistres
  • Suppression planifiée à la fin de la durée de conservation après clôture

Build stepsÉtapes de réalisation

  1. Claim tableA Claim table with the type (water damage, car accident, theft, and so on), date, description, status and a link to the contact. The claim number is generated automatically.
  2. Turn on SharePoint document managementI connect Dataverse to SharePoint and enable document management on the Claim table, so each claim gets its own folder automatically.
  3. Declaration form in Power PagesA short form with a file-upload area. On a phone, the browser offers to take a photo directly.
  4. Lock down types and sizesI set the allowed extensions and maximum size on the form and check them again on the server side, so the browser isn't the only line of defence.
  5. Table permissions"Signed-in customer" can create claims and add files only on their own claims, using the contact scope from module 2.
  6. Route each fileA flow runs when a file arrives. An image goes to AI photo analysis (module 5) and a PDF to form extraction (module 6). The claim status becomes "Received – being analysed".
  7. Customer confirmationAn email confirms the claim number and the list of files received. The customer can track the status in "My space".
  8. RetentionA scheduled flow deletes files a set number of years after a claim closes. This is the same pattern I run in production today.
  1. Table des sinistresUne table Sinistre avec le type (dégât des eaux, accident auto, vol, etc.), la date, la description, le statut et le lien au contact. Le numéro de sinistre est généré automatiquement.
  2. Activer la gestion documentaire SharePointJe relie Dataverse à SharePoint et j'active la gestion documentaire sur la table Sinistre, pour que chaque sinistre ait automatiquement son dossier.
  3. Formulaire de déclaration Power PagesUn formulaire court avec une zone de dépôt. Sur mobile, le navigateur propose de prendre une photo directement.
  4. Verrouiller types et taillesJe fixe les extensions autorisées et la taille maximale sur le formulaire, et je les vérifie de nouveau côté serveur, pour que le navigateur ne soit pas la seule protection.
  5. Autorisations de table« Client connecté » peut créer des sinistres et ajouter des fichiers uniquement sur ses propres sinistres, grâce à la portée contact du module 2.
  6. Orienter chaque fichierUn flux se déclenche à l'arrivée d'un fichier. Une image part vers l'analyse photo (module 5), un PDF vers la lecture de formulaire (module 6). Le sinistre passe au statut « Reçu – en cours d'analyse ».
  7. Confirmation au clientUn e-mail confirme le numéro de sinistre et la liste des fichiers reçus. Le client suit le statut dans « Mon espace ».
  8. ConservationUn flux planifié supprime les fichiers un nombre d'années défini après la clôture du sinistre. C'est le même mécanisme que j'exploite aujourd'hui en production.
