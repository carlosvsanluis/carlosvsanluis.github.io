Secure customer loginConnexion client sécurisée

Customers create an account and sign in with multi-factor authentication. Once signed in, each customer can see only their own quotes, claims and documents. Advisors sign in separately with their company account.

Le client crée son compte et se connecte avec une authentification multifacteur. Une fois connecté, chacun ne voit que ses propres devis, sinistres et documents. Les conseillers se connectent séparément avec leur compte d'entreprise.

Two kinds of userDeux types d'utilisateurs

  • Customers: a Microsoft Entra External ID account (email and password, or a one-time code) with MFA, used on the Power Pages portal
  • Advisors: the company's Entra ID account with Dataverse security roles, used in the back-office app
  • Clients : compte Microsoft Entra External ID (e-mail et mot de passe, ou code à usage unique) avec MFA, utilisé sur le portail Power Pages
  • Conseillers : compte Entra ID de l'entreprise avec rôles de sécurité Dataverse, utilisé dans l'application back-office

Build stepsÉtapes de réalisation

  1. Create the Power Pages siteI start from a blank template inside the AssurDemo solution and give it Home, My space, Quotes and Claims pages.
  2. Set up Entra External IDI create an external tenant and a sign-up / sign-in user flow (email and password, or a one-time code), turn on MFA, and apply the insurer's branding.
  3. Connect it to Power PagesI add External ID as an OpenID Connect provider, switch off local logins and the other providers, and set a session timeout.
  4. Link each account to a contactOn first sign-in, the portal creates or matches a Dataverse contact. That record is what every permission check relies on.
  5. Web roles and table permissionsA role called "Signed-in customer" has Contact-scope permissions. Customers can read their own quotes, claims and files, create new ones, and nothing more.
  6. Lock down the back officeAdvisors get least-privilege security roles: "Advisor" and "Senior advisor" (who can approve). Sensitive columns such as bank details are protected with column security.
  7. Pass the identity to the chatbotI configure authentication in Copilot Studio so that "my policy" questions use the signed-in customer's identity and data.
  8. Try to break itI open another customer's record by changing the ID in the URL (it must fail), call the portal's Web API without a role, and check HTTPS, cookie and header settings.
  1. Créer le site Power PagesJe pars d'un modèle vierge dans la solution AssurDemo, avec les pages Accueil, Mon espace, Devis et Sinistres.

Security and complianceSécurité et conformité

Consent and a privacy notice at sign-up, MFA for every customer, auditing turned on, and no credentials stored in Dataverse: the identity provider holds them. That last point is the lesson from my real-world password migration work.
Consentement et mention d'information RGPD à l'inscription, MFA pour chaque client, audit activé, et aucun identifiant stocké dans Dataverse : c'est le fournisseur d'identité qui les gère. Ce dernier point est la leçon de mon travail réel de migration des mots de passe.
